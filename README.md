**本地验收同步（2026-10-21）**：54 项回归通过；实际安装成功，并使用真实 v2.2.0 目录副本完成分片下载、增量安装及全部 1,053 个文件校验，覆盖失败回滚、断点续传和用户资料保留。v2.3.0 安装包约 20.1 MiB、整包约 24.3 MiB、v2.2.0 增量包约 6.51 MiB。此前界面优化的三组交替测量中，记录切换中位耗时由 285.24 ms 降至 54.72 ms；详见 `优化验收.md`。数据仅代表本轮测试场景；真实多屏截图、实际票据 OCR 准确率仍需使用者核对。正式下载入口见 [GitHub Releases](https://github.com/Lyan-ing/reimburse/releases) 或 [Gitee Releases](https://gitee.com/lyan110/reimburse/releases)，源码推送不等同于附件发布完成。

一个完全离线的 Windows 台账工具：按“报销项目 → 费用记录 → 材料槽位”的方式，半自动整理一次出差、参会或采购的报销材料，并生成可直接打印的 Word。

与旧版“扫描文件夹后猜材料类型”不同，v2 由人确定项目结构，软件负责收集素材、识别填充、检查缺失、排版 Word。自动 OCR 只做辅助，识别不准时可以随时改。

## 核心流程

1. 设置“台账目录”。
2. 新建报销项目：项目名、类型、起止日期、报销人、部门。
3. 添加费用记录：交通费、住宿费、打车费、采购、参会、其他。
4. 每条记录按模板显示素材槽位：
   - 交通：发票 + 支付记录；可选行程单、其他材料
   - 住宿：发票 + 支付记录；可选其他材料
   - 打车：发票 + 支付记录 + 行程单；可选高速费发票（可多张）。高德合并多段行程开一张发票时，支付记录可以放多笔，软件按多笔合计
   - 采购：发票 + 支付记录；金额超过 500 元时实物照片必填
   - 参会：会议注册费发票 + 支付记录 + 中文录用通知 + 英文录用通知
   - 其他：发票 + 支付记录；可选其他材料
5. 每个槽位支持：
   - 选择文件
   - 粘贴剪贴板里的图片或文件
   - 截图：调用 Windows 系统截图（覆盖所有显示器、不同 DPI 也无偏差），截取后自动粘贴为素材；按 ESC 取消则软件立即恢复、不添加素材
6. 添加发票/支付/行程单后，如开启“OCR 辅助”，会后台识别并预填金额、日期、发票号、销售方；识别结果可修改。
7. 时间自动识别，识别信息放在素材槽位下方；识别不到时再手动改。
8. 项目、记录、素材自动保存，随时生成 Word。
9. 在左侧历史台账中按项目状态管理：
   - 整理中
   - 已整理好材料
   - 已打印提交
   - 已报销完成
10. 支持搜索、状态筛选、编辑项目、删除项目、导入已有文件夹。

## 台账目录结构

每个报销项目是一个文件夹：

```text
台账目录/
  西安参会_20261017-1019/
    project.json
    assets/
      20261019_215501_高铁票.png
      20261019_215507_高铁支付.png
    output/
      报销材料_西安参会_20261017-1019_合计3,592.39元.docx
```

- `project.json` 保存项目、记录、槽位和状态。
- `assets/` 保存复制进来的素材，不依赖原始文件位置。
- `output/` 保存生成的 Word。
- 删除项目时文件夹会移到台账目录的 `_回收站`，不会直接永久删除。

## Word 顺序

按费用类别分块输出，块与块之间分页：

1. 交通类：该类证据（发票/行程单等）→ 分页 → 该类支付记录
2. 住宿类：该类证据 → 分页 → 该类支付记录
3. 打车类：该类证据（行程单与发票同页）→ 分页 → 该类支付记录
4. 其他类（会议注册费、采购等）：该类证据 → 分页 → 该类支付记录
5. 录用通知/会议通知

- 证据与支付记录之间分页，不混在一页；同属证据的可同页，同属支付记录的可同页（两列）。
- 同一类别内按业务日期排序。
- 不生成标题、封面、页码。
- 所有材料放在无边框表格中，A4 纵向。
- 文件名自动带总额，例如：

```text
报销材料_西安参会_20261017-1019_合计3,592.39元.docx
```

## 金额规则

- 有支付记录：按支付金额计入。
- 没有支付记录：按发票金额兜底，并在待补提醒中标注。
- 打车支付包含高速费、纸质票据时，按实际支付金额。
- 支付有优惠时，按实际支付金额。
- 支付截图上标注“已退款”时，显示“支付金额 / 退款金额 / 净支付”，总额按净支付计算。
- 页面底部的“支付金额（多笔净额）”可以手动修正。
- 每条支付记录素材上可直接编辑金额，或用「🧮 计算」做加减乘除后填入；改动后该记录总支付金额自动按各笔净额重新合计。手动改过的金额不会被重新识别覆盖。
- 旧素材识别不准确时，可以点槽位顶部的“识别”重新识别。
- 发票金额与支付金额差异较大时提示核对。

## 支持的素材格式

- PDF（文字层优先，扫描件走 OCR）
- OFD 电子发票
- XML 电子发票
- JPG / PNG / BMP / TIFF / WEBP
- DOCX / XLSX / EML / HTML 等

OFD、旧版 Office 等格式可以识别字段，但 Word 中可能以提示页代替原图；建议转成 PDF 后作为素材。

## 运行环境

- Windows 10 / 11，64 位
- 无需安装 Python、Office 或其他运行库
- 材料整理、OCR 与 Word 生成均离线，不上传材料；只有主动点击“软件更新”才访问更新服务器
- 设置保存在 `%APPDATA%\ReimburseOrganizer\settings.json`

## 从源码运行

```powershell
python app.py
```

旧版自动扫描界面：

```powershell
python app.py --legacy
```

无界面自测：

```powershell
python app.py --selftest "材料文件夹" --event-type 参会 --output "输出.docx"
```

安装与更新包工具位于 `tools/make_release.py`、`tools/installer.iss`；本地快捷打包脚本 `build.ps1` 不放在代码仓库中。

## 本地开发验证

以下为维护者本地验证方式；测试、性能基准和验收脚本仅留本地，不随软件源码提交。

```powershell
python -m unittest discover -s tests -p test_design_regressions.py -v
```

`tools/benchmark_ui.py` 使用独立演示台账测量窗口与记录切换，支持 `--dpi` 检查 Tk 缩放布局，不读取真实台账。

`tools/make_release.py --output-dir <独立目录> --base-url <下载基址>` 可在独立目录试打包，不覆盖现有 `dist/`；不会上传或发布。默认采用 onedir，保留 JPG/PNG/BMP/TIFF/WEBP、PDF 和 Office 支持，排除未承诺支持的 AVIF 解码器等非必要依赖。

## 已知边界

- 低分辨率手机截图可能识别错金额/日期，OCR 只做预填，请核对。
- 截图调用系统自带截图工具，覆盖所有显示器；若个别环境系统截图无响应，可改用“选择文件 / 粘贴”。
- 打车支付、高速费和其他材料支持多份；单张发票、单张实物照片等通常只放一份。
- 参会中文/英文录用通知分别放两个槽位；如果是一份中英文合并文件，可以两个槽位都选同一份。
